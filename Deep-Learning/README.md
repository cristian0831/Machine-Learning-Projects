# Music Generation with a Character-Level LSTM

Generate folk-style music with a recurrent neural network. The model reads music written as plain text (ABC notation), learns which character tends to follow which, and then writes new tunes one character at a time. The generated text is converted to MIDI and then to audio so you can listen to it.

Notebook: [Music_Generation.ipynb](Music_Generation.ipynb) (based on the MIT 6.S191 *Introduction to Deep Learning* Lab 1, Part 2).

## Goal

Treat music as a language-modeling problem: given the characters seen so far, predict the next one. Training on many tunes teaches the network the structure of ABC notation (headers, bar lines, note durations, repeats), and sampling from it produces new tunes that can be played back.

## What the notebook does

1. **Setup** – installs and imports TensorFlow, `mitdeeplearning`, and Comet ML (experiment tracking).
2. **Dataset** – loads the ABC tunes, prints an example, and plays it back.
3. **Vectorization** – builds the character vocabulary and the `char2idx` / `idx2char` lookup tables, then converts all songs into one long integer array.
4. **Training batches** – `get_batch` samples random windows of `seq_length` characters as inputs and the same window shifted by one character as targets (next-character prediction).
5. **Model** – `Embedding` → stateful `LSTM` (1024 units) → `Dense` (one logit per character), built with `build_model`.
6. **Untrained-model check** – runs a batch through the untrained network to verify shapes and shows that its predictions are noise.
7. **Training** – sparse categorical cross-entropy loss, Adam optimizer, a `@tf.function` training step using `tf.GradientTape`, periodic checkpoint saving, and loss logging to Comet ML.
8. **Generation** – reloads the checkpoint into a `batch_size=1` model and runs `generate_text`, which feeds each sampled character back in as the next input.
9. **Playback** – splits the generated text into individual songs, converts each valid one to audio (ABC → MIDI → WAV), displays a player, and saves `output_<i>.wav`.

Default hyperparameters: 200 training iterations, batch size 8, sequence length 100, learning rate 5e-3, embedding size 256, 1024 LSTM units. Increase `num_training_iterations` for better results.

## Dataset

- 817 folk tunes written in ABC notation, bundled with the `mitdeeplearning` package (`mdl.lab1.load_training_data()`), so nothing has to be downloaded by hand.
- ABC notation is a text format for music: each tune has a header (`X:` index, `T:` title, `M:` meter, `L:` note length, `K:` key) followed by the notes and bar lines.
- The tunes contain 83 unique characters, which is the vocabulary the model works with.

Example:

```
X:1
T:Alexander's
M:C|
L:1/8
K:D Major
(3ABc|dAFA DFAd|fdcd FAdf|gfge fefd|(3efe (3dcB A2 (3ABc|!
```

## Installation and setup

Tested on Linux (Ubuntu) with Python 3.10. Training runs on CPU; a GPU is optional.

1. **System packages** (needed to turn ABC text into audio):

   ```bash
   sudo apt-get install abcmidi timidity
   ```

2. **Python environment**:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   pip install comet_ml mitdeeplearning opencv-python-headless tqdm
   ```

   `requirements.txt` does not list the last four packages, so they are installed separately. `opencv-python-headless` is required because `mitdeeplearning` imports `cv2` but does not declare it as a dependency.

3. **Comet ML API key** – the notebook logs metrics and audio to Comet ML. Create a free account, generate an API key, and replace the value of `COMET_API_KEY` in the first code cell. Do not commit your key to a public repository.

4. **Run the notebook**:

   ```bash
   jupyter lab Music_Generation.ipynb
   ```

   Run the cells in order. Training writes weights to `training_checkpoints/my_ckpt.weights.h5`, which the generation section loads.

## Notes

- The notebook is committed without embedded audio players (they made the file over 50 MB). Listen to the `.wav` files above, or re-run the playback cell locally.
- The LSTM is `stateful`, so the batch size is fixed when the model is built. Training uses a batch size of 8 and generation rebuilds the model with a batch size of 1 and loads the same weights.
